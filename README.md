## ChatGPT 和 Codex 的区别：一个陪你聊，一个直接动你的代码

两者都在同一个 OpenAI 账号下，常常还是同一批模型，但工作方式完全不同。

ChatGPT 是聊天窗口：你描述问题，它吐一段代码，你复制出来自己跑，报错再贴回去。小问题够快，但它看不见你的仓库、依赖和真实运行结果。

Codex 是代理（agent）。它能读你的代码库、直接编辑文件、执行命令和测试，然后根据结果继续迭代。可用的入口包括：

- 网页端和桌面应用的 Codex 入口
- Codex CLI（命令行工具，开源，Apache-2.0 协议）
- IDE 扩展，覆盖 VS Code、Cursor、Windsurf
- iOS 端
- 云端任务，附带自动代码审查和 Slack 集成

所有入口都用 ChatGPT 账号登录，走的是你订阅里的额度，不需要另外付费。对 Plus 用户来说，这就是“包在订阅里”最实际的部分。

## Plus 的 Codex 用量限制：按 token 计费之后，额度到底怎么算

2026 年 4 月 2 日起，OpenAI 把 Plus、Pro、Business 套餐的 Codex 计费从“按条数估算”改成了按 token 折算积分（credits），4 月 23 日覆盖了全部存量 Enterprise 套餐。改完之后，同样算“一条消息”，改一个函数和跑一个长会话，消耗完全不是一回事。

Plus 的用量以 5 小时滚动窗口计算，官方给出的本地消息估算区间是这样的：

| 模型 | Plus 每 5 小时本地消息（估算） |
| --- | --- |
| GPT-6 Astra | 约 5–45 条 |
| GPT-6.1 Sol | 约 15–160 条 |
| GPT-6 Sol | 约 15–150 条 |
| GPT-6 Luna | 约 350–3,000 条 |

区间这么宽，就是因为计费跟着 token 走。上下文长短、工具调用次数、输出长度都会影响消耗，官方也明确说这些是估算值，不是硬性条数。云任务通常比本地消息更耗额度，每周上限也可能叠加生效。

几条容易踩坑的规则，值得单独列出来：

- **额度是共享的。** Plus 上的本地消息、云任务、ChatGPT 聊天，还有 ChatGPT for Excel 这类功能，吃的是同一个池子。你跑一下午 Codex 长任务，剩下的聊天额度会明显变少。
- **速度模式更贵。** Fast 模式按约 2.5 倍消耗订阅额度，Ultrafast 模式约 8 倍。
- **图像生成消耗快。** 平均比普通对话快 3–5 倍，而且 Free 套餐不可用。
- **超额不会立刻断。** 正在进行的这一轮任务允许跑完；之后 Plus 和 Pro 用户可以购买额外积分继续用，所有人也都能改用自己的 API key 按 API 价格跑本地对话。
- **查额度有两个地方。** Codex 设置里的 Usage 面板，或者 CLI 里输入 /status。

还有一个时间点需要留意：10 月 14 日起，GPT-5.5 会从 ChatGPT、ChatGPT Work 和 Codex 的所有套餐中退役，API 不受影响。如果你习惯手动选模型，记得避开它。

## 容易被忽略的一点：Plus 的 Codex 能跑脚本和 CI，但这不等于 API

Codex CLI 有个非交互模式叫 codex exec，官方文档明确支持把它放进脚本和 CI 流程，配套的还有官方 SDK 和 GitHub Action。没有显示器的服务器上也能通过设备码流程登录。换句话说，一份 $20 的 Plus 订阅可以承担程序化任务，全程不需要 API key——这是官方设计，不是什么漏洞。

但别把它和 API 混为一谈。Plus 不包含 API key，不包含 API 额度，API 的按 token 价格也没有任何折扣。OpenAI API 是独立产品、独立计费，你的 $20 一分都抵扣不了 API 账单。需要常驻 CI、多人共享的自动化、服务端调用时，老老实实用 API 计费更合适；另外 API key 模式下，云任务这类订阅功能是不可用的。

有第三方服务商测算过，Plus 的 Codex 用量折算成 API 费用大约相当于每月 700 美元。参考即可：额度是滚动窗口而不是预算，官方也会随时调整限额，别把它当成承诺。
